// Reto 01 · Fundamentos

Arranque profesional de un proyecto

Crear desde una carpeta vacía, sin copiar, la base de cualquier proyecto y comprobar que el JavaScript se ejecuta. Repítelo hasta hacerlo en menos de 5 minutos.

Concepto

  • Boilerplate — "estructura mínima que se repite en cada proyecto".
  • Reset CSS — "anular los estilos por defecto del navegador para partir de cero".
  • Custom properties — "variables de CSS": se declaran --color-bg: #0b0d0c; y se usan con var(--color-bg).
  • box-sizing: border-box — "el ancho incluye el padding y el borde".
  • type="module" — "el archivo JS es un módulo: puede usar import y export".
  • defer — "descarga el JS sin bloquear y lo ejecuta cuando el HTML ya está leído".
  • DevTools / Consola — "herramientas del navegador" (F12). Ahí ves los console.log y los errores.

Prueba

Ejemplo mínimo, incompleto a propósito. Resuelve los 4 huecos.

<!doctype html>
<html lang="es">
<head>
  <!-- 1. codificación de caracteres -->
  <!-- 2. viewport para móvil -->
  <title>Mi proyecto</title>
  <!-- 3. enlazar CSS -->
  <!-- 4. enlazar JS como módulo -->
</head>
<body>
  <h1>Funciona</h1>
</body>
</html>

Reto

  1. index.html con los 4 huecos resueltos y el lang correcto.
  2. css/styles.css con un bloque :root (mínimo 3 variables: fondo, texto, acento), el reset sobre *, *::before y *::after, y un body que use las variables.
  3. js/script.js que imprima en consola un mensaje que identifique el archivo.
  4. Responde: ¿type="module" necesita defer? ¿Por qué?

Cómo comprobar que funciona

  • La consola muestra tu mensaje y ningún error en rojo.
  • El h1 no tiene margen por defecto y el fondo usa tu variable.
  • En DevTools > Elements, al seleccionar body, ves tus variables en Computed.

Pistas

Pista 1: el JS no carga o la consola habla de CORS

Los módulos no funcionan abriendo el archivo con doble clic (file://). Necesitas un servidor local ("un mini servidor en tu equipo"). En este proyecto ya lo tienes: compose.yml sirve public/ con nginx.

Pista 2: el atributo que falta en el script

Busca en MDN "script type module" y fíjate en cuándo se ejecuta cada tipo de script.

Solución

Ábrela después de intentarlo 
<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mi proyecto</title>
  <link rel="stylesheet" href="css/styles.css">
  <script type="module" src="js/script.js"></script>
</head>
<body>
  <h1>Funciona</h1>
</body>
</html>
:root {
  --color-bg: #0b0d0c;
  --color-text: #e6ebe8;
  --color-accent: #3dff8b;
}

*,
*::before,
*::after {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

body {
  min-height: 100dvh;
  background-color: var(--color-bg);
  color: var(--color-text);
  font-family: system-ui, sans-serif;
  line-height: 1.6;
}
console.log('[mi-proyecto] script.js cargado');

Por qué así: los módulos ya se ejecutan en diferido, así que defer sobra con type="module". Con un script clásico (sin type="module") sí lo pondrías. El prefijo [mi-proyecto] te deja filtrar tus mensajes cuando la consola se llene.

Variación

Cuando lo domines: crea js/utils.js con export function saludar(nombre) {} e impórtalo desde script.js. Si funciona, entendiste los módulos.
